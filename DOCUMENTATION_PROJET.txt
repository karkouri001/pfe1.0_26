- Creation du venv .venv et installation de Django + djangorestframework
- Creation du projet Django "plateforme" et de l app "gestion"
- Configuration settings.py (INSTALLED_APPS, LANGUAGE_CODE=fr, TIME_ZONE=UTC, DEFAULT_AUTO_FIELD)
- Creation des modeles (Profil, GroupeAcademique, Examen, Soumission, Resultat, JournalAudit)

- Ajout API REST (serializers, viewsets, router, urls)

2) Architecture rapide du projet
- manage.py : commandes Django
- plateforme/ : settings.py, urls.py, asgi.py, wsgi.py
- gestion/ : models.py, admin.py, serializers.py, views.py, urls.py, migrations/
- db.sqlite3 : base SQLite locale
- requirements.txt : dependances Python

3) Modeles et relations (gestion/models.py)
- Profil : OneToOne User, role (ETUDIANT/ENSEIGNANT/ADMIN)
- GroupeAcademique : nom, annee_academique, membres M2M User
- Examen : titre, description, heure_debut, heure_fin, statut (BROUILLON/PUBLIE/EN_COURS/FERME), cree_par FK User, groupes_autorises M2M GroupeAcademique
- Soumission : trace_id UUID unique, examen FK Examen, etudiant FK User, url_depot_git, hash_commit, soumis_le auto, statut (EN_ATTENTE/EN_TEST/CORRIGE/ECHEC), unique(examen, etudiant)
- Resultat : OneToOne Soumission, note, feedback, corrige_le auto
- JournalAudit : utilisateur FK User nullable, action, horodatage auto

4) API REST (Django REST framework)
Base: /api/
Ressources:
- /api/examens/
- /api/groupes/
- /api/soumissions/
- /api/resultats/

Operations CRUD par ressource:
- GET /api/<ressource>/        (liste)
- POST /api/<ressource>/       (creation)
- GET /api/<ressource>/{id}/   (detail)
- PUT/PATCH /api/<ressource>/{id}/ (modification)
- DELETE /api/<ressource>/{id}/ (suppression)

7) Tests unitaires et CI/CD
- Tests unitaires BACKEND: ils sont ecrits par l equipe dev dans le code (ex: gestion/tests.py).
- Ces tests valident la logique API/Modeles de la plateforme et tournent avec python manage.py test.
- Tests de CORRECTION par examen: ils sont fournis par chaque enseignant via un repo Git (url_tests_git + hash_tests optionnel).
- Flux: l enseignant cree un examen avec url_tests_git -> l etudiant soumet son depot ->
  le CI clone le repo etudiant + le repo de tests -> execute -> envoie le resultat via /api/webhook/resultats/.
- Le webhook cree/met a jour Resultat et met a jour Soumission.statut.
- Le CI/CD orchestrera ces deux types de tests sans les melanger.

8) Documentation REST API complete (a copier)

Base URL (local):
- http://127.0.0.1:8000/api/

Format:
- JSON uniquement
- URLs avec slash final (ex: /api/examens/)

Ressources:
- examens
- groupes
- soumissions
- resultats

Authentification / Permissions:
- Par defaut DRF (aucune restriction configuree dans settings.py).
- Acces ouvert tant que vous ne changez pas les permissions.

Codes HTTP courants:
- 200 OK (GET)
- 201 Created (POST)
- 204 No Content (DELETE)
- 400 Bad Request (validation)
- 404 Not Found (id inexistant)

---
Ressource: Examens

GET /api/examens/
-> Liste des examens

POST /api/examens/
Champs:
- titre (string, requis)
- description (string, optionnel)
- heure_debut (datetime ISO 8601, requis)
- heure_fin (datetime ISO 8601, requis)
- statut (string, choix: BROUILLON, PUBLIE, EN_COURS, FERME)
- cree_par (int, id User, requis)
- url_tests_git (string URL, optionnel)
- hash_tests (string, commit optionnel)
- groupes_autorises (liste d ids GroupeAcademique, optionnel)

Exemple POST:
{
  "titre": "Intro Python",
  "description": "Examen 1",
  "heure_debut": "2026-01-29T09:00:00Z",
  "heure_fin": "2026-01-29T11:00:00Z",
  "statut": "BROUILLON",
  "cree_par": 1,
  "url_tests_git": "https://github.com/enseignant/tests.git",
  "hash_tests": "abc123",
  "groupes_autorises": [1, 2]
}

GET /api/examens/{id}/
PUT/PATCH /api/examens/{id}/
DELETE /api/examens/{id}/

Ressource: Soumissions

GET /api/soumissions/
POST /api/soumissions/
Champs:
- examen (int, id Examen, requis)
- etudiant (int, id User, requis)
- url_depot_git (url, requis)

Exemple POST:
